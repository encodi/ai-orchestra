# The web interface: user guide (Milestone 9)

```sh
ai-orchestra web            # then open http://127.0.0.1:8765/
ai-orchestra web --port 9000 --open
```

It runs on your computer only. Opening or refreshing the page **never calls an agent**; only pressing
**Enviar / Send** does. The terminal commands (`consult`, `chat`, `debate`, `mcp serve`) keep working, and the
browser uses the same history, memory and saved defaults as they do. Stop it with Ctrl-C; a running
consultation is cancelled and recorded as cancelled.

Screenshots (generated by the browser tests): [`docs/screenshots/`](screenshots/), for example
`desktop-dark-chat-result.png`, `desktop-dark-theater.png`, `desktop-light-research.png` and
`mobile-dark-chat-result.png`.

## Chat (home)

Type a question and press **Enviar** (or Ctrl/⌘ + Enter). While it runs you see the **stages** that have
started (planning, web research when used, independent analysis, review, synthesis), each agent with its
state, the seconds elapsed, and **Cancelar**. There are no percentages and no text that types itself: the CLIs
return an answer when they finish, so only recorded facts are shown. A refresh reattaches to the same
consultation without repeating any call.

The result has four tabs:

* **Respuesta** - the coordinator's answer as Markdown (tables and code included). A citation `[n]` is a
  button only when source *n* was retrieved by AI Orchestra itself; it opens that source. Follow-up
  suggestions are fixed templates (not model output) that fill the question box. Feedback is stored locally.
* **Agentes** - every agent's recorded contribution, expandable. A failed call is shown as a failure.
* **Investigación** - sources and claims (below).
* **Detalles** - mode, strategy, calls, time, tokens *only if the CLIs reported them*, the memory context
  that was recalled (an estimate, labelled as such), the **settings in force and where each came from**, the
  routing decisions and warnings.

A **follow-up** continues the same AI Orchestra session through memory (the session id is shown in the
header). **Nueva conversación** starts a new one. **Ver plan** shows what a question would do - mode, agents,
strategy, recalled context - without calling anything.

A partial result says **Parcial** and why; a failed one says what failed; a cancelled one says it produced
no result. None of them is ever shown as complete.

### Settings for this consultation

**Ajustes de esta consulta** opens every setting, built from the server's own list (the same as the terminal
chat): mode, strategy, coordinator, participating agents, review rounds, length, web search, research depth,
maximum sources, source freshness, time per agent, maximum calls, maximum duration, parallel calls, memory
and context budget, and the view. Each is **Auto** until you set it, and **Volver a Auto** returns it.

Two scopes are kept apart: **solo esta pregunta** (used once, then forgotten) and **esta sesión del
navegador** (kept for this tab, not saved anywhere). A third layer, your **saved defaults** (Ajustes →
Valores por defecto), is the starting point of every consultation, in the browser and in the terminal.
Precedence, strongest first: safety rules > this question > this session > saved defaults > automatic. A
value you set is never silently replaced; a combination that cannot be honoured is refused *before* anything
runs, with the field named. Choices no provider can support are disabled with the reason.

Optional HTTPS pages can be added (they are downloaded by AI Orchestra; agents do not open them), and
"remember this consultation" can be turned off.

## Agent Theater

The same consultation as a conversation between the agents, with the three pixel robots. Everything in it
is a recorded message or event; see [agent-theater.md](agent-theater.md). Open it from a result
(**Ver en el Teatro**), from History (**Reproducir**) or from the sidebar. Switch between **Teatro** and
**Transcripción**; replay a saved consultation with **Reproducir desde el inicio**.

## History

Search (words in the question or answer), filter by mode, strategy, agent, status and dates, page through
results. Each item can be opened, replayed, exported as JSON or deleted (after a confirmation that explains
what is and is not removed). Consultations older than 30 days that used web research carry a notice: prices,
versions and availability may have changed, and **opening one does not check anything again**. A consultation
with a memory session can be continued.

## Investigación (research and sources)

For consultations that used the web: the sources AI Orchestra **retrieved** (title, domain, a safe link,
published/updated/retrieved dates and age, the literal passages used as evidence) kept apart from
**candidates** that were reported or found but not retrieved (not evidence), and every claim with its status
(`Apoyada`, `Contradicha`, `Evidencia mixta`, `Evidencia insuficiente`, `No comprobada`), who made it, the
passages for and against, and how many independent sources stand on each side. Whether a passage supports a
claim is read by a model and is labelled model-dependent; the status is computed from those links, never
from agreement between agents. A consultation without web research says so plainly.

## Informes

*Mediciones*: real measurements of the consultations saved on this machine (durations, calls, failures by
strategy, mode and agent; tokens only where a CLI reported them). The memory context reduction is labelled
an **estimate**. *Evaluaciones*: the Milestone 8 evaluation runs, each with its provenance (fixture, mock,
recorded, live) and a sentence saying what that means. Nothing here invents a saving, a cost or a quality
claim; with no data the page says so.

## Memoria

Search memories (scope and origin are on every record), add one (it is stored **only** after you tick the
explicit confirmation), correct one (the old version is kept, marked as replaced), delete one, export all.
Records marked sensitive are masked unless you ask to reveal them and are never sent to an agent. *Sesiones*
lists this project's sessions (continue or clear one). *Vista previa de contexto* shows what a question would
recall, sending nothing.

## Ajustes

*Valores por defecto*, *Apariencia* (theme: dark - the default, light, or follow the system; language:
Spanish or English; animations: follow the system, reduced, full; open new consultations in the theater),
*Agentes* (executable, `--version`, capabilities and locally measured history for each CLI; whether you are
signed in is shown as **unknown** because it cannot be known without a real call, and this page never makes
one) and *Seguridad* (the rules that always hold).

## Teatro animado, conversación, resumen y personajes (v0.9.1)

**Teatro animado sobre el chat.** Al enviar una pregunta se abre un pequeño escenario pixelado encima de la
conversación: los tres personajes caminan por una sala (cada uno a su escritorio mientras analiza; juntos a la
mesa durante la revisión; el coordinador pasa al frente para redactar; al terminar se alinean) y, cuando un
agente termina de hablar, le sale una burbuja con **sus propias palabras** (recortadas) y su nombre debajo. Lo
que camina es decoración que sigue la etapa real; lo que dice una burbuja es siempre un mensaje registrado,
nunca texto inventado. Un fallo muestra "No pudo responder", no el error ni palabras. Con "movimiento
reducido" nadie camina. Se oculta con **Ocultar teatro** o en Ajustes → Apariencia. Debajo está el mismo chat de
siempre.

**Texto de espera.** En lugar de "en curso / trabajando", el panel muestra frases de teatro y orquesta que
cambian solas y siguen la **etapa real** ("afinando los instrumentos" mientras cada uno analiza, "el director
repasa la partitura" en la síntesis, "bajando el telón" al cancelar). Es solo ambientación: no indica cuánto
falta. Un lector de pantalla recibe un estado estable ("En curso: Revisión") y con movimiento reducido la frase
no rota.

**Conversación.** La primera pestaña de un resultado reciente es **Conversación**: lo que dijo cada agente como
burbujas, agrupado por lo que hacía el grupo ("cada uno pensó por su cuenta", "se revisaron entre sí", "se
respondieron entre ellos", "el coordinador redactó el informe"). Mientras corre, la conversación aparece
mensaje a mensaje. Para que se sientan hablando entre ellos, en la revisión cada agente recibe la instrucción de
dirigirse a los demás por su nombre (se puede apagar en Ajustes → Personajes); las primeras respuestas no
ven a nadie más, así que siguen siendo independientes. Si un agente muestra tokens, aparecen en su burbuja.

**Idioma.** Cada llamada que redacta lleva la instrucción de responder en el idioma de tu pregunta (o en el
que elijas en Personajes) sin mezclar idiomas. Los títulos de sección los pide el motor en inglés porque los lee
de vuelta; la interfaz los muestra traducidos (la respuesta guardada y su exportación conservan el original).
Los avisos que genera el propio motor (por ejemplo las "Notas del motor") siguen en inglés.

**Resumir.** Cuando termina, **Resumir el reporte** pide al coordinador (o a quien elijas entre los que
participaron) un resumen corto del reporte. Es **una** llamada, solo ocurre si pulsas, se puede cancelar y el
resultado se marca como escrito por ese modelo ("condensa, no verifica"). Se guarda con la consulta y vuelve a
verse desde el Historial. El resumen solo usa lo que dice el reporte.

**Personajes** (Ajustes → Personajes). A cada agente le puedes dar un **nombre**, una **personalidad** (texto
libre de hasta 600 caracteres, con ejemplos para empezar) y un **aspecto** (3 paletas y 4 accesorios: ninguno,
lentes, gorra, audífonos). El nombre se usa en toda la interfaz (con el nombre real del CLI al lado) y, junto con
la personalidad y el idioma, se escribe en las instrucciones de las llamadas que redactan (no en el plan de
búsqueda ni en la comprobación de afirmaciones). Importante: una personalidad es una instrucción de
interpretación de papel; **no da conciencia ni mente a un modelo, no cambia lo que puede hacer** (siguen en solo
lectura) y **sí puede cambiar lo que dice una respuesta**; por eso una consulta que usó personajes lo deja anotado
(sin copiar el texto de la personalidad). El aspecto es solo visual.

**Informes → Uso por agente.** Para cada agente: llamadas y tokens (entrada / salida / en caché) **tal como los
informó su CLI**, en total, en las últimas 5 horas, 24 horas y 7 días, una gráfica por día de los últimos 14, y
las veces que un CLI avisó de que llegó a su límite. Un CLI que no informa tokens muestra "–", nunca ceros ni
estimaciones. **Cuánta cuota te queda por sesión, día o semana no se muestra**: ni Claude Code, ni Codex, ni
Antigravity la exponen de un modo que AI Orchestra pueda leer sin llamar a un modelo ni abrir sus archivos
privados (su estado de cuota solo está en sus pantallas interactivas), y no se inventa. Los números son
ventanas móviles sobre las consultas guardadas en esta computadora.

## Keyboard

| Keys | Action |
|---|---|
| Ctrl/⌘ + Enter | send the question |
| `/` | go to the question box |
| Alt + 1 … 7 | Chat, Theater, History, Research, Reports, Memory, Settings |
| Alt + N | new conversation |
| `?` | list the shortcuts |
| Esc | close a dialog |

Tabs use the arrow keys; dialogs trap focus and return it when closed; there is a "skip to content" link; the
live regions announce progress politely. Contrast is checked automatically (WCAG 2 AA, both themes) and the
pages work at phone width with a bottom navigation bar. With reduced motion the robots and notices stop
moving.

## First live three-agent consultation (needs your authorization)

Nothing in this milestone called a real model. When you decide to try it:

1. `ai-orchestra doctor` - the three CLIs installed and signed in.
2. `ai-orchestra web --open`, then in **Ajustes de esta consulta** choose strategy `thorough` and leave the
   agents on Auto (or select all three).
3. Ask something that deserves three opinions and press **Enviar**. It spends subscription quota of each
   CLI; watch the stages, then open **Ver en el Teatro** and replay it from History afterwards.
